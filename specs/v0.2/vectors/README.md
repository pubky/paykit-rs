# Paykit v0.2 test vectors

Test vectors for Paykit's own wire format in `specs/v0.2/wire-format.md`: its amounts, derivations, the Paykit
member of app records, the executor grant, messages and shared record values. Every file is computed from fixed keys and fixed
randomness by `paykit-lib`'s vector tests (How the files were generated, below), so any implementation can check them byte for
byte.

**This set builds on no vector of [the Switch's set](https://github.com/pubky/pubky-switch/tree/28562dc9095d09e1d9b28d1fe7faa9c0f4d676e3/spec/vectors), at pubky-switch commit `28562dc9095d09e1d9b28d1fe7faa9c0f4d676e3`, the commit Paykit's spec builds on**: its fixed keys, certificates and records are its own (`keys.json`, `documents.json` `certificates`), and its seeds, encodings and times follow that set's conventions.

## Conventions
- **Seeds.** Every fixed secret and random value of this set is `BLAKE3("paykit/v1/test-vectors/" + label)`, cut to the length needed, as the Switch set seeds its own under its own prefix; `keys.json` gives each key's label, and the nonce of `sealed.json` `labelled` is the seed of `sealed/labelled/nonce`. No key, certificate or record of the Switch set is used. Encodings and times follow the Switch set's conventions.
- **Sections.** Descriptions and the table above cite sections of `specs/v0.2/wire-format.md` as "wire N"; "spec N" is the Paykit v0.2 spec, and "Switch wire N" and "Switch spec N" are the Pubky Switch's documents.
- **Allowance usage.** An entry counts by its own `outcome`, else by the state of its attempt's claim listed in `claims` (`open` and `unknown` reserve, `done` spends, `failed` releases, missing spends). `refused_by` is the limit that refuses a candidate.
- **Permissions** (Switch wire 3.1, wire 3.1). The switch checks a certificate's `permissions` for form and enforces them as signed; Paykit's verifiers check them against Paykit's scopes: every permission those need, and, in a certificate without another protocol's scope, no other.
- **Rejections.** Where a file lists inputs to refuse (`documents.json` `certificate_rejections`, `labelled_scope_rejections` and the `refused` cases of `app_records` and `multi_protocol_certificates`, `sealed.json` `binding_rejections` and the rejections of `labelled`, `messages.json` `label_rejections` and the `refused` cases of `multi_protocol_senders`, `cancellation_roles`, `conversion_terms` and `proof_members`, the `refused` cases of `messages.json` `receipt_members`, of `documents.json` `executor_certificates` and `payer_certificates`, of `sealed.json` `activity_records`, its `later_writes`, and `allowance_records`, and of `allowance_usage.json` `period_limit_spellings` and `period_limit_members`), what is normative is that the input is refused. An `error` or `reason` text is the wording of the code that generated the case, quoted without the section number it starts with there, and only informative.

## How the files were generated
`paykit-lib`, the v0.2 Paykit Library, generates every file but `encoding.json` in its vector tests (`paykit-lib/tests/vectors/`), from the seeds above, with `pubky-switch-core` for the Switch's algorithms. Ed25519 signs deterministically and every nonce comes from a seed, so nothing needs other randomness. What a case is about, such as a message's JSON, its times, amounts and IDs, is written in the files; every value computed from it, such as a key, an ID, a hash, a signature, a sealed value or a certificate, is generated. `encoding.json`'s cases are written by hand, and the tests check each normalized value against `paykit-lib`'s decimal parser. The tests run with `pubky-switch-core`'s test-only `test-vectors` feature, and no production build has it.

The same tests check every case byte for byte and verdict for verdict: they build each value again and compare it with the file, the switch takes each certificate and record, every signature verifies, every message passes the recipient checks and decodes by kind, and Paykit's readers and verifiers take or refuse each case as its list says. Anyone can run them: `cargo test -p paykit-lib --test vectors`. In `cancellation_roles` a certificate holding `paykit_pay` holds `paykit_contacts` too.

After an intended wire change, the same tests run with `PAYKIT_WRITE_VECTORS` set write the files again, and their diff shows every value the change moved.

The JSON examples in `specs/v0.2/wire-format.md` are taken from these files; update them with the vectors.
