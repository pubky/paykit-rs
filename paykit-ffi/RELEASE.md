# Releasing paykit-ffi

## Prerequisites

Use Rust 1.91.1 or newer with Cargo and rustup. Building all bindings requires
macOS with Xcode and its iOS device/simulator SDKs selected for `xcrun` and
`xcodebuild`, plus the Android SDK (API 34), Android NDK, and JDK 17. Configure
`ANDROID_HOME`, `ANDROID_NDK_ROOT`, and `JAVA_HOME` for those installations. The
build scripts install the required Rust targets and binding generators.

Before releasing, check the remote tags and published releases and choose the
next unused version. Update crate/dependency versions, `Cargo.lock`, the Android
version, and the `Package.swift` release tag and checksum together for the same
source revision. Upload the exact XCFramework zip whose checksum was committed;
a new build requires a matching new artifact and checksum. Do not reuse an
already published tag or replace its artifacts.

## 1. Build

From `paykit-ffi/`:

```bash
./build.sh -r --rc all           # RC: 0.1.0 → 0.1.0-rc1 → 0.1.0-rc2 → ...
./build.sh -r --minor --rc all   # Minor RC: 0.1.0 → 0.2.0-rc1
./build.sh -r all                # Finalize RC: 0.1.0-rc2 → 0.1.0
./build.sh -r --patch all        # Patch: 0.1.0 → 0.1.1
```

This bumps the version consistently in `paykit-ffi/Cargo.toml`,
`paykit-lib/Cargo.toml`, `paykit-sdk/Cargo.toml`, the SDK's `paykit-lib`
dependency, the root `Package.swift`, `gradle.properties`, and the React Native
`paykit-react-native/package.json` and `package-lock.json`, then builds both
platforms and updates the `Package.swift` checksum. It does not build the React
Native package; CI does that when publishing.

The iOS release zip is generated at:

```text
paykit-ffi/dist/ios/Paykit.xcframework.zip
```

Android generated Kotlin, JNI libraries, native debug symbols, and Gradle build
outputs are intentionally ignored and regenerated by `build_android.sh` or CI.

Always build all platform bindings together with `all` so Swift and Kotlin stay
in sync. The internal `build_ios.sh` and `build_android.sh` scripts are only for
local sub-build debugging.

## 2. Commit

```bash
git add -A
git commit -m "Release v<VERSION>"
git push origin HEAD
```

## 3. Create GitHub release

1. Go to https://github.com/pubky/paykit-rs/releases/new
2. Select the tag, attach `paykit-ffi/dist/ios/Paykit.xcframework.zip`.
3. Publish.

iOS consumers resolve the SPM package from this release automatically.

iOS release upload automation is intentionally deferred. SwiftPM validates the
release asset against the checksum committed in `Package.swift`; a CI rebuild
can produce a different zip checksum unless CI owns the full release
transaction. See the vss-rust-client-ffi decision context:
https://github.com/synonymdev/vss-rust-client-ffi/pull/22#issuecomment-5330226070

## 4. Publish Android

The `Gradle Package` workflow triggers automatically on release publish. If it didn't, run it manually from Actions → "Gradle Package" → Run workflow with the version.

The workflow publishes with the job's built-in `GITHUB_TOKEN`, which its `permissions` block grants `packages: write`, so it needs no repository secret.

## 5. Publish React Native

The `npm Package` workflow (`.github/workflows/npm-publish.yml`) triggers
automatically on release publish. It checks out the release tag, builds the iOS
XCFramework on macOS and the Android libraries on Ubuntu, and checks that
`paykit-react-native/package.json` has the tag's version. It then runs
`npm run pack:check` and publishes `@synonymdev/react-native-paykit` with npm
provenance. Release candidates get the `next` dist-tag, so `latest` stays on the
last final release.

The workflow needs the `NPM_TOKEN` repository secret, an npm automation token
that can publish the package.

To check a release without publishing, run it manually from Actions ->
"npm Package" -> Run workflow with the version. A manual run builds the same tag
but only runs `npm publish --dry-run`; it never publishes. If a release run
fails, re-run its failed jobs.
